SİSTEM ADMIN KURULUM
1- multi-tenant plugin install & import & config
2- tenant koleksiyonu oluştur, plugin config'de tenantsSlug degerini duzenle. otomatik olarak DB'de users_tenants tablosunun oluştuğunu gözlemle. Bu sekilde uygulama ilk ayaga kalktiginda create-user form açılır ve ilk kullanici tenant iliskisi olmadan create edilir. login olduğunda Posts gibi (eğer oluşturulduysa) tenant iliskili duzenlenmis koleksiyonlara ve tenant koleksiyonuna admin panelinde erisemez. mevcut olan user ve media koleksiyonlarına eriştiği gözlemlenir. bu koleksiyonlara erisimleri de ileriki adımlarda duzenlenmelidir. users koleksiyonu sadece sistem admin yönetmelidir. diğer tenant bazlı kullanıcılara kapatılmalıdır (upsert, delete)
3- user koleksiyonunda sistem yöneticisi için role yapisi olustur. admin ve user rolleri tanımla. Bu roller tenantı olmayan kullanıcılar için atanacak. sistem admin sayısı birkaç kullanıcı ile sınırlı olacak.
4- onInit'de varsayilan ilk user'i sistem admin rolü ile düzenle. böylece uygulama ilk ayaga kalkıp DB create edildiginde sistem admin user default olarak olusturulur. 
5- payload.config'de plugini "useTenantsCollectionAccess:false, " olarak ayarla. Böylece tenants koleksiyonu access control metotlarını varsayılan kullanımını devredışı bırakıp sistem admin ve tenant bazlı kullanıcılar için özelleştir (best-practice) 
6- sistem adminin tenants yönetimine erişebilmesi için tenants access control read metodu ayarlarında user.role=='admin' için tam yetki ver (return true). böylece dashboard'da tenants koleksiyonu sistem admin tarafından yönetilmeye başlasın ve ilk tenantları ve tenant bazlı kullanıcıları oluştursun. 
7- sistem admininin tenants koleksiyonunu admin panelinde yönetebilmesi ve erişebilmesi için tenants koleksiyonunun access control read metodu override edildi. override edilmeden önce varsayılan olarak tenanta bağlı kullanıcıların tenant bazlı koleksiyonlardaki işlemleri, tenant switch mekanizması ve user'ın bağlı olduğu tenant bilgisini okumak için bu metot kullanılır. bu metodu ezdiğimiz için req.user.tenants verisi kontrol edilerek user'ın bağlı olduğu tenantid'leri query olarak döndürülür ve tenants koleksiyonu access control read metodunun kullanılması düzenlenir. bu ayarlanmazsa user tenant bazlı koleksiyonlarda işlem yürütemez, tenant switch çalışmaz.
8- userHasAccessToAllTenants: god mode on. tenant'ı olmayan ilk kullanıcının tenant ile ilişkili diğer koleksiyonlara erişebilmesi için user parametresinde role değeri üzerinden yetki verilir. userHasAccessToAllTenants user.role=='admin' ile ayarlanır. Böylece sistem admini tenants yönetimi ile birlikte tenant bazlı diğer koleksiyonlara erişimi sağlanır ve bu erişim tenant switch ile yönetilebildiği gözlemlenir
9- tenant bazlı kullanıcının tenants koleksiyonunu admin panelinde görmemesi için tenants koleksiyonu admin ayarlarında tenants.admin hidden düzenlemesi yapılır ve sadece user.role=='admin' için admin panelinde tenant koleksiyonu gösterilir
10- pluginin tenantsArrayField ayarlaması ile Users koleksiyonu içinde user-tenant ilişkisinin (array type) düzenlenmesi sağlanır. Bu ayar best-practice'de Users koleksiyonunda array tipinde ve içinde tenants ve role fieldlarının olduğu alanları içerir. Bunun için includeDefaultField:false olarak düzenlenir ve Users koleksiyonunda tenantsArrayField exportu kullanılarak düzenlenir.
